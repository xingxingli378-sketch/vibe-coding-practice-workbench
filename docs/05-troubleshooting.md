# 故障排查：先看现象，再决定改什么

|现象|优先定位|下一步|
|---|---|---|
|python/node/npm找不到|安装或PATH|重新打开CMD并检查版本|
|Pillow导入失败|使用的Python环境|用`.venv`里的Python安装和启动|
|Qwen显示未安装|npm依赖或Node|项目根目录运行`npm install`，检查Node22+|
|已安装但API连接失败|模型服务、代理、账号配置|在Qwen官方交互界面验证同一服务|
|编辑提示必须先读取|工具前置条件|要求重新读取目标文件再编辑|
|没有shell工具|此次会话能力或审批|用页面检查按钮，不反复委派|
|程序运行但检查失败|实现与题目差异|把预期/实际/失败原文交给Qwen|
|检查通过但输出文件不存在|只验证了函数或临时目录|让Qwen执行题目要求的最终run入口|
|回复完成但页面一直忙碌|事件解析或CLI进程结束|停止助手、检查文件、独立运行检查；保留事件用于排查|
|旧会话不存在|resume编号过期|按页面提示重新发送；不需要直接重配账号|
|修改网页后仍是旧页面|缓存或服务未重启|关闭旧服务、重新启动、Ctrl+F5|
|中文检查在另一台Windows报编码错误|子进程标准输出编码|检查程序已固定UTF-8；不要仅靠开发机环境变量|
|8765端口被占用|旧服务或其他程序|确认归属后关闭旧服务，不盲目结束进程|

## 错误层次

连接错误：请求没有到达可用模型服务，不代表题目代码错。
工具错误：例如文件未读或命令工具不可用，不代表算法错。
程序错误：运行代码报错或结果不符合题目，才进入实现调试。
页面/服务错误：忙碌标记、旧题号、输出解析错误，需要检查工作台。

停止进程可能产生非零退出码；这不能单独证明账号失效。项目对用户主动停止单独处理，普通失败也只提示定位实际运行记录。

## 如何提交一份有效错误报告

```text
题号：
我执行的操作：
输入材料：
完整错误：
题目预期：
实际结果：
刚修改的文件：
```

不要只发送“还是不行”。也不用先懂全部术语，完整证据比猜测原因更有用。

## 版本相关限制

Qwen事件格式和权限能力可能随版本变化。当前代码针对固定版本解析system、assistant、result等事件。若更新后无法结束，先保留真实事件，不把任意一段assistant回复当成最终结束。

本地版没有学校独立容器的隔离、真正隐藏评分或考试纪律系统。它适用于学习流程，不适合作为正式考试平台直接部署。
