# 项目演进与实际调试记录

这里记录真实经历和后续改进，省略个人账号、路径和聊天记录。

## 第一阶段：三道基础题

工作台已有三题，分别训练图片读取、数据清洗和成绩汇总。通过网页中的Qwen进行修改，文件预览只读。修改前独立运行检查，基线分别是8/10、7/10、2/10。

01失败于首帧RGB像素为空和缺少不确定标记；02是占位实现，把有效记录全部拒绝；03缺少输入校验与计算。修改后分别独立检查达到10/10。没有因“助手解释很长”就判定完成。

过程中Qwen编辑工具要求先重读文件，随后修正。当前会话又缺少直接运行命令的工具，于是改用网页检查按钮。实际环境限制不能推断为Qwen所有版本都没有shell能力。

第三题公开通过后，代码审阅发现先做有限性判断会让超大整数触发另一种异常。调整为类型后先判断范围，再判断有限性，并重跑公开检查。这是公开用例之外的审阅发现，当时没有单独运行该超大整数自定义输入。

## 第二阶段：把调试方法改成新手行为模板

最初解释包含较多Python术语，对零基础用户不够友好。随后改为固定循环：读题→建立基线→修改实际文件→立即运行→样例通过后检查特殊情况→有改动再检查→核对交付物。

“输入”解释成给程序的材料，“输出”解释成结果。用户提供真实错误，Qwen负责寻找技术原因，不要求用户预先想到OverflowError等情况。

官网页面正文嵌入PDF，网页文本抓取一开始没有得到具体说明，后来读取PDF才确认三题、两小时、Qwen作答、公开与隐藏检查，以及气象图像例题。正式三题内容并未公开。

新增04–06，增加多文件、批量容错、输出文件、去重、误差和可读报告。04明确是合成示意图与离线七段数字辅助识别，并非真实气象OCR。

独立参考实现验题：04公开10/10，加练15/15；05/06公开10/10，加练16/16。实际作答保持待实现状态。

## 第四阶段：服务更新与项目整理

已有后台进程不会因源码修改自动加载新的题号。原环境无法控制那个进程，因此提供用户手动重启方式，并在页面注明需要重启。没有将“已写入文件”说成“服务已经上线”。

GitHub版本进一步去掉个人绝对路径、运行依赖、对话和账号配置。题库与作答分离；启动器使用项目自己的虚拟环境；正常结束与用户停止分别处理；加入无模型CI和独立验题入口。

收到CLI最终result后收尾的改动已用模拟事件测试；真实Qwen账号、网络、模型响应仍需在配置账号后的本地环境验证。

首次GitHub Actions运行还发现Windows默认控制台编码与开发环境不同，中文JSON输出会失败。修复为检查程序自身固定UTF-8，并增加非UTF-8控制台回归测试，避免只在开发电脑上能运行。

## 做项目时学到的判断方法

把功能问题、工具问题、连接问题、服务问题分开；每次修改用同一方法检查；公开通过后核对特殊情况；最终检查文件，而不是只检查回答。
