# 如何新增题目并确认题目可做

## 一道题必须有四类材料

1. README：场景、输入、输出、异常、边界、修改范围、交付文件、样例预期。
2. 素材：能覆盖正常与特殊情况，声明真实来源或合成方式。
3. 待实现代码：给入口名称，不把答案填好。
4. 检查：检查行为，不绑定唯一代码写法，不只比样例文件名。

先给出一份人工算清的预期结果，再写检查。否则可能发生“代码错了、测试也错了，两者恰好一致”。

## 本项目的进阶设计

04 加入改名、不同尺寸、JPEG、GIF第二帧误导、时间不清楚、坏图隔离和输出文件。辅助模块读取合成图上实际七段数字像素，不根据名称返回时间。内容分类定义是本题的合成色占比规则，不推广成真实气象分类标准。

05 加入多 CSV 来源、BOM、摄氏华氏转换、最后有效记录去重、第一失败原因、来源行号、按日期汇总。原始范围判断在舍入之前；无效重复不能覆盖有效记录。

06 加入完整站点时间键配对、未配对与无效分别计数、未舍入阈值判断、零分母、误差方向，以及 JSON 和 HTML 一致性。HTML 中的站点文字要转义。

## 作者验收

```cmd
.venv\Scripts\python.exe tests\author_qa.py
```

脚本复制原题库到独立 `work/author-qa`，写入验题参考实现，分别运行公开与加练检查。预期04为10/10与15/15，05/06为10/10与16/16。不会改 `tasks`。

参考实现只证明这些检查能被正确程序通过，不证明检查覆盖了题目所有可能情况。还应审查题面、样例和预期值。

## 增加第七题需要同步改哪里

- `task_bank/07/`：README、QWEN、数据、实现入口。
- `server.py`：TITLES、task题号范围、选择检查程序的规则。
- `index.html`：导航按钮、标题数组、训练目标数组、总题数、是否启用加练按钮。
- 检查脚本：入口文件映射与题目分支，保持JSON报告结构。
- `tests`：初始题库检查预期、独立验题。
- `README`：目录和题目说明。

当前版本有些题目元数据同时保存在前后端，不能只加一个文件夹就认为切题完成。修改后重启服务、刷新浏览器，并实际测试切题、预览和检查。
