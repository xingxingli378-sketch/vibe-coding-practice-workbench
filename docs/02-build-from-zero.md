# 从零创建这个项目：完整流程

这篇说明为什么要有各个文件、它们如何配合，以及每一步怎么验收。完整可运行代码就在仓库里，不需要照着文字重新猜代码。

## 第一步：先确定产品要求

我们要做的是一个本地练习网页：题面和素材可查看；作答文件只读；用户通过 Qwen 修改实际文件；检查显示真实结果；六题各自保存；模拟模式连续计时两小时。

不做的范围也要明确：不冒充学校平台，不预测正式题，不实现公网多用户服务，不把提示词指引当成容器隔离。依据是[学院公开说明](https://www.sii.edu.cn/2026/0930/c24a1242/page.htm)，具体正式安排仍以学校通知为准。

可以给编程助手的创建请求：

> 请创建一个仅本机访问的 Vibe Coding 练习网页。题目与文件预览只读，用户通过真实 Qwen Code 对话修改实际文件；显示工具记录与真实检查结果。题目目录、对话独立保存，刷新不重置两小时计时。先给文件结构和最小实现方案，不使用模拟助手回复。

**验收：**它提出的方案必须有“文件保存在哪里”和“检查如何执行”，不能只有漂亮网页。

## 第二步：划分文件职责

|文件|职责|
|---|---|
|`index.html`|页面布局、题号、预览、对话、检查和轮询|
|`server.py`|本地 HTTP 接口、Qwen 子进程、检查子进程、状态保存|
|`task_bank/`|可复制的题目原始模板|
|`prepare.py`|只补齐缺失模板到作答目录|
|`checker.py`|基础三题公开检查|
|`advanced_checker.py`|进阶公开与加练检查|
|`launch_qwen.py`|打开 Qwen 官方配置流程|
|`requirements.txt` / `package.json`|声明依赖及版本|
|`tests/`|验证基础设施与题库，不调用模型|

创建目录后，先写依赖文件，安装依赖。先不要写满所有页面与题目。

## 第三步：先完成最小网页与服务

从 `server.py` 末尾看入口：用标准库 `ThreadingHTTPServer` 监听 `127.0.0.1:8765`。根路径 `/` 读取 `index.html`。页面请求状态和文件接口。

最小版本先验证：服务能启动、页面能打开、能列出一个题目目录、能读取 README。请求的文件路径必须在当前题目目录内。

助手请求：

> 先完成服务启动、一个题号、文件列表和只读 README 预览。确认是真实读取磁盘文件。其他功能暂缓。完成后给出启动命令和实际访问结果。

**验收：**在磁盘修改 README 后刷新文件，网页内容随之改变，证明不是把内容硬写在页面中。

## 第四步：接入真实 Qwen

查看 `server.py` 的 `cli()`、`settings_env()`、`run_job()`。安装 npm 依赖后，通过 Node 调用本项目的 Qwen 入口；当前工作目录设为所选题目的目录。

核心参数：

```text
qwen -p <用户请求> --output-format stream-json --approval-mode auto-edit
```

`-p` 提交请求；逐行 JSON 用于展示文本、工具记录和结束结果；`auto-edit` 并不等于所有命令自动获准。实际语法和事件格式需要对照固定版本及[官方 Headless 文档](https://github.com/QwenLM/qwen-code/blob/main/docs/users/features/headless.md)。

账号配置放在 Qwen 官方流程，不由网页收集。子进程命令用参数列表构造，不把用户文本拼成一段 shell 命令。

请求模板：

> 接入已安装 Qwen CLI。把用户请求作为独立参数传入，工作目录限定为当前题目录。逐行解析 stream-json，显示真实文本和工具记录，记录会话编号以便继续对话。不启用 yolo。无法调用时显示真实错误，不生成假回复。

**验收：**先发只读请求，再发一次可逆的文件编辑请求，刷新文件确认真实修改。连接标签和长回答都不是修改成功的证据。

## 第五步：设计后台任务与状态

模型调用和检查可能耗时，不能在页面请求里一直阻塞。`run_job()` 创建后台线程；`JOBS` 保存运行状态与事件；页面每隔一段时间读取 `/api/job`。

`practice-state.json` 保存每题对话、会话编号、检查结果、模式与开始时间。写入采用临时文件替换，并使用锁保护并发修改。

三个结束分支必须处理：正常结束、用户停止、异常/超时。不能只处理“模型成功回复”。本项目收到最终 `result` 后结束流读取；若进程仍不退出，短暂等待后收尾，避免页面一直显示忙碌。必须以对应版本的实际事件为依据。

**验收：**正常回复能释放按钮；停止调用不被误报为账号失效；失效会话编号能清理；刷新页面保留状态。

## 第六步：编题与独立检查

先写输入、输出、异常和修改范围，再生成素材、放入待实现代码，最后编检查。检查不能为了匹配某个答案临时改标准。

初始文件保存在 `task_bank/01` 等目录，`prepare.py` 复制到 `tasks`。检查只加载实际作答文件。每个检查捕获失败并生成 `name/ok/detail`，最后输出 JSON；单项失败不会阻止其他检查显示。

出题请求：

> 请先写完整题面，给出样例的预期输出，再创建素材、待实现代码和十项公开检查。额外设计特殊输入验证。用独立参考实现检查题面和测试一致，不把答案写进学习者目录。

本项目所有进阶验题在独立副本里进行；临时交付目录在 `.check-work` 下，检查完成自动清理。检查不会偷偷替用户生成最终作品。

## 第七步：补齐网页操作

页面调用的主要接口：

|接口|用途|
|---|---|
|GET `/api/state`|题名、安装状态、计时、持久化状态|
|GET `/api/files?task=N`|当前题文件列表|
|GET `/api/file?task=N&path=...`|代码、文字或图片预览|
|POST `/api/chat`|开始 Qwen 调用|
|POST `/api/check`|公开检查；进阶可带 `extra:true`|
|GET `/api/job?task=N`|当前运行状态和工具事件|
|POST `/api/stop`|停止助手|
|POST `/api/clear`|清当前题对话，不删作品|
|POST `/api/mode`|开始模拟或切回练习|

请求带本次服务生成的随机令牌。页面显示用户文字使用 `textContent`，不是任意 HTML 注入。文件路径解析后必须仍属于当前题目录。服务只监听本机。

**验收：**切题时标题、文件和对话一致；不读取题外文件；坏图能显示失败信息；禁止同时重复发送；检查结束后按钮恢复。

## 第八步：补齐计时与交付核验

开始模拟时记录服务器时间，剩余时间由开始时间加7200秒减当前服务器时间计算，刷新和切题不重置。到时禁止新的调用和检查；已运行任务可能仍在结束，这是本地教学版本的限制。

每题最终核验实际输出文件。公开全过不能证明其他输入都正确，更不能当作学校最终满分。

## 第九步：验证、清理、提交

运行基础设施测试和独立验题。检查 Python 语法与页面脚本语法。账号不可用时，测试页面和检查逻辑仍然可以进行，不能捏造一次真实模型调用。

Git 只提交源码、原始题库、说明和测试。排除作答、对话、账号配置、依赖和临时文件。使用相对路径，移除开发电脑上的专属绝对路径。

最终应做到：新目录安装依赖 → 初始化六题 → 配置自己的账号 → 启动网页 → 实际作答 → 检查 → 输出交付文件。做到这条流程，项目才可以复现。
